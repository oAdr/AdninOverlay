Adnin v23 - Lunar / Badlion / Vanilla Minecraft 1.8.9 x64

The usage ZIP contains exactly Adnin.exe. The program embeds its Lunar and
Badlion/Vanilla DLL payloads, icon and third-party notices. No Forge installation,
ClientSideSounds JAR, audio pack or sidecar DLL is required.

Updating
1. Exit a game process that already has an older Adnin DLL loaded, then restart
   the supported 1.8.9 client. Do not inject a second version into the same process.
2. Double-click Adnin.exe with one supported game window open. The injector
   selects the matching payload and displays success or failed in one window.
3. A successful result closes after its two-second countdown and fade. A failed
   result stays open and offers Export log. The red dot closes either result.
4. In game, use /config to open the menu.

New in v23
- Cache positive teammate names and UUIDs for the current match. Temporary
  respawn/spectator states, Tab disappearance, entity replacement and a local
  entity tick reset do not erase an already confirmed teammate.
- Never use light gray `§7` as a self or teammate color. A teammate already
  confirmed earlier in the same match remains cached while briefly gray.
- Pause all five Anticheat checks and new queries/denick work for light-gray
  players. Suppress their new local/party announcements; retain known player
  data, Nick/Denick identity, tags and teammate decisions across gray respawns.
  Party IDs ignores newly observed gray players without erasing earlier groups.
  White `§f` and dark gray `§8` are not light gray.
- Repair Lunar Party Detector IDs recovery: only a validated `/locraw` response
  completes the cycle; transient missing-player/sidebar/sender failures can
  retry up to three times with five seconds between attempts and a fresh 500 ms
  waiting-room check. Lobby, active game and Replay restrictions remain.
- The settings header now displays `v23`.
- Read decoded server-mode packets before Lunar consumes them; retire responses
  on scope/connection changes and pass verified modes to the native detector.
- Recheck gray names before generated chat and party delivery, including cached
  stats/tags and conflicting respawn colors. Existing player state is retained.
- Ping now uses the public Aurora v2 endpoint independently of the API Proxy
  switch. No Ping API key is sent. The current asynchronous worker/cache are
  retained: completed results 10 minutes, request failures 45 seconds.

Historical v19 changes

  responses last ten minutes, failures cool down for 45 seconds, and refreshes
  happen only at a detected game entry. Completed content and valid in-flight
  requests survive world changes. Key changes retire pending work but preserve
  completed content; new requests use the current key.
- Bot Denicker keeps verified matches and explicit no-result responses for ten
  minutes, and transport/account-verification failures for 45 seconds. These
  results survive matches and worlds. Changing the Bot URL or toggle clears them.
- Replay profile lookup caches verified identities and confirmed [NICK] results
  for ten minutes; failures use 45 seconds. Native Skin and Number Denicker
  caches already survive matches, and keep their original cache lifetimes.
- Team recognition uses your displayed nametag color, even when you use a
  server Nick. A different self Tab UUID is linked only by a unique visible
  name; your self identity stays separate from teammates. Confirmed teammate
  decisions remain fixed for this match and reset for the next match/context.
  Missing or ambiguous identity/color evidence is not guessed.
- Output is gated to game or Replay and is split into Player Data, Nick /
  Denick, Seraph / Urchin Tags and Anticheat. All four default off. Tag Output
  has Include Self and Include Teammates switches, both initially on.
- Leaving a game/Replay discards queued party messages. Verified cached Bot
  results can announce once per eligible match without another HTTP request.
- Replay roster helpers reuse bounded scratch collections and reduce recurring
  regex work; fresh negative Bot cache entries avoid duplicate lookup hints.
  These are code/fixture improvements, not a measured live FPS guarantee.
- v19 verification is offline. This pass did not inject a live game, make API
  requests, or send party messages/report commands.

Runtime limits
Both payloads target the analyzed Windows x64 Minecraft 1.8.9 runtimes. They do
not claim compatibility with every modified client or other Minecraft versions.
The real GuiIngame tick hook is installed independently of Session Stats.
Genuinely missing/backward/stalled samples still restart detector evidence;
the detector does not invent observations. Scaffold uses the Mellow port
described in the v17 evidence, and its timing is not guaranteed at accelerated
Replay speeds. Use 1x playback when checking detections. No client-side check
covers every bridging technique or every incomplete recording.
These client-side checks are heuristic alerts, not authoritative proof.

The current verification report is in 验证状态.md in the source archive.
Build, ABI, signed-loader, menu and in-memory packet tests are offline evidence.
The new modules have not been verified in a live Lunar/Badlion/Vanilla session.
No real chat, party message or report command was sent during these tests.

Settings and privacy
All clients use %LOCALAPPDATA%/Adnin/config.properties. It stores every API key,
custom Bot URL, feature option, Output, Anticheat, language, scale and columns.
First startup without that shared file imports the latest valid native settings
in Adnin's old payload cache and the current client's old feature settings once.
An existing shared file always wins, including empty credentials.
Old files are preserved; Lunar, Badlion and Vanilla no longer save separate files.
Changes save atomically on the existing worker after a short debounce.
API keys and the custom Bot URL start empty on a clean installation. Replacing
the EXE on the same PC reuses saved settings; it does not embed them in the EXE.
No personal settings, API keys or custom Bot URL are included in the release.
Do not distribute your settings file. Public Urchin/Mojang service endpoints
remain part of the existing program. Supported software-generated UI and errors
follow the selected English, Simplified Chinese or Traditional Chinese language.
API reasons, names and received chat keep their original content.

Retained features
Urchin game-entry queries and content cache, colored tags and names, FK/LV,
configured Tab order, Bot/Skin denicker support and party Output remain present.
Party Output removes only a leading [Adnin] and splits only when the selected
client's accepted chat-packet size requires it. Bot failures remain local.
