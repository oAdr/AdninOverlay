Adnin v18 - Lunar / Badlion / Vanilla Minecraft 1.8.9 x64

The program embeds Lunar and
Badlion/Vanilla DLL payloads, icon and third-party notices. No Forge installation,
ClientSideSounds JAR, audio pack or sidecar DLL is required.

New in v18
- Fixed a discarded JNI Future reference in the Lunar scheduler.
- Added a narrow process-exit guard for the native CRT thread-destructor path.
  Explicit module unload still uses its original cleanup.
- Reused UI direct buffers and released textures on menu close, world change
  and explicit unload. Optional cleanup failures no longer abort HUD ticks.
- Stopped optional API/Replay workers on unload and prevented late results from
  repopulating cleared queues. Cross-match Urchin content has an extra budget.
- Reduced temporary allocations when loading embedded Java helpers.

Previous v17 changes
- Fixed inherited OpenGL state causing jagged and comb-like rounded edges.
- Settings > Interface: UI Scale (70-140%) and English / Simplified Chinese /
  Traditional Chinese. The language preference also applies to injector results.
- Direct Hypixel requests use the current UUID endpoint and API-Key header.
  Failed cache entries expire when the configuration is edited.
- Replaced only Scaffold with Mellow's logic; existing other checks remain.

Previous v16 changes
- The settings panel has smooth system fonts, rounded controls, animated
  navigation/switches/scrolling, opening and closing transitions, and a red
  close button. It scales to fit the viewport without hidden clickable rows.
- Full Replay Tab names take priority over short profile aliases, including
  names split across formatting codes or scoreboard-team suffixes.
- Blank Hypixel keys no longer silently choose a proxy. Vega Proxy must be
  explicitly enabled for proxy statistics and ping. Settings show the selected
  source or missing key. Existing cached statistics can remain visible.
- Number's separate key now updates when the visible key is changed or cleared.
  Requests accepted before configuration synchronization may still complete.

Retained v15 changes
- Replay uses the normal red [NICK] display for an explicit absent-account
  result. Timeouts, API errors and pending requests remain placeholders.
- Existing Skin, Number and Bot Denicker paths also support confirmed Replay
  Nick rows. Resolved account statistics do not replace the recorded actor UUID.
- Anticheat matches normalized Replay names and raw aliases even with colored
  names or extra display suffixes. Nick eligibility does not require successful
  account lookup. Replay detections never generate WDR commands.
- Chat Overlay has three independent Output switches: Player Data, Seraph /
  Urchin Tags, and Anticheat. Player Data includes Nick and all Denicker results.
  Messages use /pc. Turning a category off removes its pending fragments.
- Prior Output settings migrate to Player Data and Tags; Anticheat Output starts
  off. Fresh installations start with all three categories off.
- Number Denicker lock contention is addressed in the native runtime. Exact
  coverage and measured versus offline evidence are listed in the verification
  report; unresolved or unavailable results remain pending for later refresh.

Retained v14 changes
- Formatted Replay profile names now use the same normalized lookup key as
  the native Tab rows. This repairs the v13 live case admitting only one player.
- Current Tab/world identity and ambiguity checks remain; normal-game bot

Retained v13 changes
- Repairs the native Replay branch that skipped statistics and showed blanks.
  Current Tab account names are resolved asynchronously to verified online UUIDs.
  The replay-bot UUID, GameProfile, name and team are not rewritten.
- Anticheat matches current replay actors by recorded Tab identity even when
  their entity, profile and Tab UUIDs differ. Ordinary-game bot filters remain.
- Alert/report cooldowns survive setting changes and temporary actor churn.
  Automatic report commands are also limited per player across detector types.
- Five-block-or-larger Replay jumps reset evidence. Replay NoFall cannot reliably
  distinguish a 5-40-block seek, so those cases are suppressed; live NoFall remains.
  Use 1x playback for detection checks. Historical actors cannot generate WDR.
- Sanitized local status now shows Replay and Anticheat counters without player
  identities, credentials, URLs or raw errors. No personal settings are packaged.

Retained v12 changes
- Removed Add cheaters as enemy, its saved-setting behavior and the bottom menu
  watermark. The license is still included in source and embedded in the EXE.
- Flag interval now has dedicated minus/plus buttons. Disabled controls and
  the 0/60-second bounds are shown correctly, including when the panel scrolls.
- A visible sidebar title or row containing replay (case/format insensitive)
  also permits the overlay. It follows the selected team-color sidebar and the
  last 15 visible rows. Hidden rows and the Tab objective do not activate Replay.
  The stats overlay still follows the current eligible Tab roster; it does not
  insert absent actors from stale Prequeue chat-name caches.
- Detector sampling uses the real game-tick callback independently of the
  Session Stats display switch. Frame/scheduled callbacks cannot consume it first.
- Legit Scaffold associates a fresh sneak edge with a nearby new swing cycle,
  repairing the phase-0 versus phase-1 timing gap. Three consecutive matching
  cycles, a held block and the downward-pitch condition remain required.

Anticheat:
- Replaces the old detector with RavenBS-Plus-Plus Autoblock, NoFall, NoSlow,
  Scaffold and Legit Scaffold checks. Old native detector calls are disabled
  in both payloads; old saved switches cannot reactivate them.
- Enabled defaults off. Each check and Flag Sound default on.
- Flag interval: 0-60 seconds, default 20, per player and check.
- Ignore teammates, Only Atlas suspect and Auto report
  are optional and default off. Ignored players accepts comma-separated names.
- Alerts are local, retain nametag colors and offer a clickable WDR action for
  valid account names. Auto report sends only after an eligible alert and must
  be explicitly enabled. Replay actors and Atlas suspects do not generate WDR.
- Enable Output: Anticheat to forward detection text to party chat. This option
  is independent of Player Data and Tags and never forwards the WDR control.

Utils -> Client Side Sounds:
- Defaults off. Enable to hear immediate local block-placement sounds during
  remote non-creative play and suppress matching delayed server echoes.
- The toggle applies immediately. It replaces the source mod's /bps command.
- Functional-block interaction, sneaking, replaceable blocks, all six faces,
  non-block items and air-use packets receive their appropriate handling.
- Singleplayer and creative mode do not add prediction sounds. Disabling the
  option restores normal server-sound forwarding.

Runtime limits
Both payloads target the analyzed Windows x64 Minecraft 1.8.9 runtimes. They do
not claim compatibility with every modified client or other Minecraft versions.
The real GuiIngame tick hook is installed independently of Session Stats.
Genuinely missing/backward/stalled samples still restart detector evidence;
the detector does not invent observations. Scaffold retains the source's
movement, no-sneak, pitch, vertical-motion and four-block-air checks, so it does
not cover every jumping, sneaking, slow or ground-supported bridge technique.
These client-side checks are heuristic alerts, not authoritative proof.

Settings and privacy
API keys and the custom Bot URL start empty. New sound and AntiCheat options are stored in that same game-local file.
No personal settings, API keys or custom Bot URL are included in the release.
Do not distribute your settings file. Public Urchin/Mojang service endpoints
remain part of the existing program. 

Retained features
Urchin game-entry queries and content cache, colored tags and names, FK/LV,
configured Tab order, Bot/Skin denicker support and party Output remain present.
Party Output removes only a leading [Adnin] and splits only when the selected
client's accepted chat-packet size requires it. Bot failures remain local.
